# Compare options

1. **Criteria.** Work out what the user cares about (budget, must-haves, deal-breakers) from the
   request and from `memory/`. If the budget or the one must-have is missing, ask once.
2. **Candidates.** Find four to eight real candidates with web search. Drop any that miss a
   must-have before spending time on them.
3. **Details.** For each remaining candidate, open the seller's or maker's own page and record
   the current price (with currency and date), the specifications that matter for the criteria,
   delivery or contract terms, and the link. With more than three candidates, give each one to a
   subagent and wait for them.
4. **Table.** One row per candidate; columns for price, each criterion and the link. Mark any
   value you could not confirm on the seller's page.
5. **Recommendation.** Name one pick and one runner-up, each with the reason in a sentence, and
   say what would change the pick.
6. Save the table to `files/comparisons/<topic>.md` if the user is likely to come back to it.

## Rules

- Prices come from pages you opened today, not from search snippets or memory.
- Reviews on a seller's own site are marketing; say where each opinion comes from.
- Do not add anything to a basket, start a checkout or sign up for anything.
