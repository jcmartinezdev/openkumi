OpenKumi keeps everything in `~/.openkumi` (override with `OPENKUMI_HOME`). Bots belong to a
person, so each person with bots on the computer has a data folder of their own in it, and a
server of their own that runs on it. Most computers have one person, made the first time OpenKumi
starts: under the name you gave the app then, or after your account on the computer.

```
~/.openkumi/
  people.json                who has bots here, and the port each one's server listens on
  people/<name>/             a person's data folder: all that follows, once for each person
    bots/<id>/
      bot.md                 yours: name, emoji, what it is for, look, voice, what it runs on,
                             and below the header, the rules the bot must follow
      superpowers.json       yours: the superpowers switched on for it (once there is one)
      workspace/             the bot's own, and the only place its file tools reach
        AGENTS.md            its instructions to itself, which it writes and updates
        memory/              its notes; only the list is loaded, it reads a note when needed
        files/               its working files (not in the history)
          inbox/             files you or another bot sent it, and its browser downloads
      private/               never visible to the bot
        browser-profile/     its Chrome profile: cookies, sign-ins
        superpowers/<id>.json  its account with the app a superpower works in
        history.git/         the record of every change to AGENTS.md and memory/
        attachments/         the conversation's copies of files sent in it
        grok/                the settings Grok is given for each turn, on a bot that runs on Grok
    openkumi.db              conversations, messages, the queue, automations and their runs, webhooks,
                             and the count of tokens the models used
    prices.json              the public list of model prices, as last fetched for the Usage page
    settings.json            app-wide settings that differ from the defaults
    auth.json                the access code, this server's id, API keys (readable only by you)
    clients.json             the computers and phones paired with this one (readable only by you)
    telemetry.json           the random id usage and error reports go under, while they are on
    logs/telemetry.ndjson    each report that was sent, as it went (see Usage and error reports)
    calls/workspace/         an empty folder Codex is started in for a call
    server.log               what a server installed alone printed in the background
  openkumi.db                not your data: a note that makes a version of OpenKumi from before
                             people had folders say it is too old, where it would start afresh
  runtime/                   only for a server installed alone: the program, not your data
    versions/<version>/      that version's server, with the Node it runs on
    current                  a link to the version that is started
```

The app's settings screens only read and write these files, so you can also read and edit them by
hand, and back the folder up like any other. `openkumi people` says what your name here is, and
`openkumi people rename` changes it. A version from before people had folders kept all of it in
`~/.openkumi` itself; the first start of a newer one moves it into your folder.

## Who owns what

<BotAnatomy caption="Three parts: yours, the bot's own, and private." />

The split is deliberate.

- **What a bot can do is yours.** Its model, rules and superpowers sit outside its workspace, so it
  cannot grant itself anything. It is told what your rules say on every turn, but cannot change
  them.
- **What a bot knows is its own.** It rewrites `AGENTS.md` and `memory/` freely. Each change is a
  commit in a git history kept in `private/history.git`, labelled with who made it (the bot, you,
  or OpenKumi when it set the workspace up), and the bot's **Workspace → Changes** can show and
  undo it. `git --git-dir=…/private/history.git --work-tree=…/workspace log` reads it by hand.
- **What a bot must never see is private.** Its sign-ins, its browser's cookies, and the history
  that lets you undo what it did.

A bot can also read, never change, the files of the superpowers switched on for it, at
`superpowers/<id>/` in its file tools. They are not in its workspace; they come with OpenKumi.

## `bot.md`

The header holds the settings, and the text below it the rules:

```md
---
name: Travel
emoji: ✈️
description: Plans trips, finds flights and hotels, and keeps the bookings in one place.
look: cat sky cap orange
provider: claude-code
model: default
web_search: true
show_browser: false
created: 2026-11-12T09:30:00.000Z
---

Never book anything over 300 euros without asking me.
Prefer trains to flights for anything under four hours.
```

Edit it by hand and the change applies on the bot's next step. A folder you make yourself, with
nothing but a `bot.md` in it, becomes a bot the next time the server starts, which gives it a
workspace.

## Files you send

A file you attach to a message first waits in `private/attachments/waiting/`, out of the bot's
sight, until you send the message (and is thrown away after a day if you never do). When you send
it, the conversation keeps its copy in `private/attachments/`; when the bot reads the message, it
gets a copy of its own in `workspace/files/inbox/`. Files one bot sends another arrive the same way.
