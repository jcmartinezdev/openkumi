An OpenKumi app can work with **several servers** (environments), and reach each one at **several
addresses**. You pair once; from then on the app finds the best way to each server by itself, at
home and away, and moves when a better way appears. This page explains how, and where to change it.

## Several servers

A computer that runs the OpenKumi server is an **environment**. The desktop app can hold several:

- **the local environment**, the server on this computer, which the app starts itself;
- **any number of remote environments**: a Mac mini in a cupboard, a computer at the office, a
  friend's server you were given a code for. Each was paired on its own and has its own key.

**Settings → Environments** lists them, each with a switch (**Use …**) and a status:

| Status | Meaning |
| --- | --- |
| Connected | it answers, and has shown it is that server |
| Not reachable | nothing answers at any of its addresses |
| No longer lets this computer in | it answers, but this computer was removed there: pair again |
| Runs an older OpenKumi, which has to be updated first | **Update it** asks it to update itself |
| Runs a newer OpenKumi than this app | update the app (**Settings → About**) |
| Turned off | its switch is off; the app does not try it |

The window shows **one environment at a time** (marked **Showing now**). **Open**, the switcher at
the top of the sidebar or of Settings, or the **People** menu switches to another; the window stays as it is and only what it is
connected to changes. The app connects only to the one it shows, so while you look at one, the
bots of the others go on working on their own computers, unaffected.

The iPhone app holds one environment at a time.

### The local environment

When the local environment is on, the app first looks for an OpenKumi server already running on
this computer, at port 4317 (or `OPENKUMI_PORT`). If one answers and proves it is the real thing,
by signing a value the app made up with the access code in the data folder, the app uses it and
leaves it running when you quit; that is how the app works with a server you installed alone on the
same computer. If nothing answers there, the app starts its own server: on port 4317, or on a free
port if 4317 is taken by something that is not an OpenKumi of yours.

The local environment is the first person's server on this computer. Where others have bots there
too, each on a server of their own, the app runs theirs while it runs yours, and shows theirs when
they are picked in its switcher. They reach theirs from their own devices as a remote environment,
on its own port
([Bots for someone else in the house](/environments/#bots-for-someone-else-in-the-house)).

## Several addresses

The same server can usually be reached in more than one way. A device keeps every address it knows
for a server, each of one kind:

| Kind | Recognised by | Plain `http`? |
| --- | --- | --- |
| **This computer** | `127.x.x.x`, `localhost`, `::1` | yes |
| **Home network** | `10.x`, `172.16–31.x`, `192.168.x`, `169.254.x`; IPv6 local addresses; a computer's own name (`mac-mini`, `mac-mini.local`, or ending in `.lan`, `.home`, `.internal`, `.home.arpa`) | yes |
| **Tailscale** | `100.64.x.x` to `100.127.x.x`, `fd7a:115c:a1e0:…`, or a name ending in `.ts.net` | no: `https` only |
| **Internet** | anything else: a public IP or a domain | no: `https` only |

They come from three places:

1. **The address you paired with**, from the code or QR code.
2. **The server itself.** Every time a device connects, it asks the server where else it can be
   reached, and the server tells it its home network addresses. (A server that does not let other
   computers connect reports none.)
3. **You.** Any address you add by hand: an IP or name on the home network, or an `https` address
   in front of the server, on Tailscale or on the internet. See
   [Away from home](#away-from-home).

## What is tried first

The addresses are put in this order, and the first one where the server answers is used:

1. **This computer.**
2. **The home network**, waiting up to 2.5 seconds for an answer.
3. **Tailscale**, waiting up to 5 seconds.
4. **The internet**, waiting up to 6 seconds.

Within each kind, the addresses the server reported come before the ones you added, and then the
order they were added in.

**All of them are asked at once**, not one after another, so being away from home costs at most
the 2.5 seconds it takes to give up on the home address. An address only wins when every address
before it has answered or given up: a home address that answers is always preferred to Tailscale,
even when Tailscale answered a moment sooner.

**Asking is not sending the key.** At each address the device asks "who are you?", with a value it
made up and a tag made from its key, and only an address that answers with a signature that only
its own server could make is a candidate. Something else at a saved address (another device that
got the same home address on another network, another OpenKumi server) is never sent the key. See
[Before a key is sent anywhere](/security/access/#before-a-key-is-sent-anywhere).

## Staying on the best address

While connected, the device asks every address again **once a minute**, and **whenever the
network changes** (the computer comes back online, or the app comes back to the front; on the
phone, whenever the app becomes active). Then:

- an earlier address that answers now wins: home again, after Tailscale;
- when the address in use stops answering, the next one that answers takes over;
- when something other than the server answers at the address in use, the device leaves it at once.

A connection can also die without closing: on a phone that was put away, or a computer that slept.
The server pings every connection every 20 seconds, so a device that has heard nothing for 45
seconds asks whether it is still there, and so does a device that comes back to the front. When no
answer comes within 5 seconds, it connects again at once and catches up on what it missed.

When no address answers, it tries again every 2 seconds, and every 5 seconds when the server
answered but refused this device or runs a version this app cannot work with. Nothing is lost in
between: what you were looking at stays on the screen from the copy the app keeps.

## Finding addresses by themselves

You pair once, wherever you are, and do not have to type an address again:

- **The server reports its addresses** each time a device connects: its addresses on every home
  network it is on. The device keeps them, in place of the ones it reported before, so a server
  that got a new home address (a new router, a move) is found at the new one, and one it no longer
  has goes away. At most eight are kept, and only home network addresses are taken from a server;
  an `https` address, on Tailscale or elsewhere, is only ever yours to add.
- **Addresses you added are never touched** by what the server reports.
- **A server that reports nothing** (one reached through a tunnel, say) never takes away the way to
  it.

## Away from home

Plain `http` is only used on the home network. Anywhere else, Tailscale included, a device needs an
`https` address for the server, and how you get one is up to you. A plain `http` address there is
refused ("Needs https"), and the server closes connections that come straight from Tailscale or the
internet.

<Steps>

1. Put something that answers at an `https` address in front of port 4317 on the computer that runs
   the bots (or the port of the person's server it is for). On Tailscale, Tailscale can give the
   computer a certificate for its name, as in `https://mac-mini.tail1234.ts.net` (see Tailscale's
   own documentation on HTTPS and `tailscale serve`). On the internet, a reverse proxy or tunnel
   with a certificate, such as `https://kumi.example.com`. Either way it has to pass requests on to
   the server on this computer, at `127.0.0.1:4317`, and say on every request, the live
   connection at `/ws` included, that it passed it on, with an `X-Forwarded-For` (or `Forwarded`,
   `X-Forwarded-Host`, `X-Real-IP`) header. Without one, the server takes the request for this
   computer itself, and a paired device could use what only this computer may, such as opening a
   bot's folder in this computer's file manager. It also has to pass on the WebSocket upgrade at
   `/ws`. `tailscale serve` does both by itself; other proxies may have to be told. In nginx, for
   one, neither is done unless set:

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:4317;
       proxy_set_header X-Forwarded-For $remote_addr;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection "upgrade";
   }
   ```

2. On each computer, open **Settings → Environments**, choose **Add address…** in the
   environment's **⋯** menu (or press **N addresses** next to it), type the address and press
   **Add address**. On the iPhone, it is the server's page in Settings.

</Steps>

The server treats what comes through such a proxy as coming from elsewhere: a paired device's key
works there, the access code of the computer itself never does, and pairing or removing devices
still only happens at that computer. On the internet, the API's door is then guarded by the paired
keys alone, so prefer Tailscale where you can.

## The settings

### On a computer

**Settings → Environments**, under each remote environment:

- the line under its name says which address is in use and of what kind: "Connected · via Home
  network · 192.168.1.20:4317" (for a computer the window is not showing, the address it would
  use);
- **N addresses** opens the list, in the order they are tried. In the environment the window
  shows, the address it is connected through has a green **In use** mark. Each of the others
  shows its kind, how it answered just now (**Answers**, **Not reachable from here**,
  **Something else answers**, **Needs https**, **No longer lets this computer in**, **Runs an
  older/newer OpenKumi**), and "reported by it" for those the server keeps up to date;
- **Remove** takes away an address you added (the ones the server reported cannot be removed: it
  keeps them up to date);
- **Add address** takes another; **Add address…** in the environment's **⋯** menu opens the list
  with the cursor already there. Type it as you like: `192.168.1.20`, `mac-mini.local`,
  `mac-mini.tail1234.ts.net` or `https://kumi.example.com`. When you leave it out, `http://` and
  the port `4317` are added to a home network address, and `https://` to any other (no port is
  added to an `https` address). Another person's server on that
  computer has a port of its own: type it, as in `192.168.1.20:4327`.

An address is checked when you add it. If something else answers there, it is refused and nothing
is sent. If nothing answers yet, it is kept, and the key goes there only once the server answers
and proves itself.

### On the computer that runs the bots

**Settings → Profile & devices → Let other devices connect** (or `openkumi lan on`) lets other devices
reach it at all; off, it listens on this computer only and reports no addresses. Below it, **Pair a
device** shows the computer's home network addresses, for typing in; the QR code carries the
first one, and the device learns the rest once it connects. Pair at home, or type the code with an
`https` address of your own.

### On the iPhone

In the phone's Settings, the server's name at the top opens its page. **Connection → Through**
says which address the phone is connected through, and of what kind. **Addresses** lists them in
the order they are tried, with a green **In use** mark on that one, and **Add** takes another, the
same way.

<Aside title="Troubleshooting">
  An environment never connects away from home: it needs an `https` address (on Tailscale or on
  the internet), added under its addresses; see [Away from home](#away-from-home). Never at home: **Let other devices connect** has to be on, and a firewall must let
  port 4317 in (and 4327, 4337 and so on, for the other people with bots on that computer). See
  [When something is wrong](/troubleshooting/#the-app-cannot-connect).
</Aside>
